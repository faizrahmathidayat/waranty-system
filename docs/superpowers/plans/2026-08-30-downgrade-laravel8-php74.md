# Downgrade to Laravel 8 + PHP 7.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the `dashboard` app (currently Laravel 10 / PHP ^8.1) install and boot cleanly on PHP 7.4 by downgrading the framework to Laravel 8 and every dependency to a PHP-7.4-compatible version, with no behavior change to the business logic.

**Architecture:** This is a dependency/runtime downgrade, not a rewrite. Three layers of change: (1) `composer.json` constraints swapped to Laravel-8/PHP-7.4-compatible versions and `composer update` run against the local PHP 7.4 binary; (2) the small number of PHP 8-only syntax constructs (nullsafe `?->`, `match()`) rewritten to PHP-7.4-legal equivalents (`optional()->`, `switch`); (3) `config/` and `bootstrap/app.php` reconciled against a real Laravel 8 skeleton so no Laravel-9/10-only config keys are silently ignored or cause boot errors. No database schema, routes, controller logic, or Blade markup structure changes.

**Tech Stack:** PHP 7.4.33 (already installed at `C:\laragon\bin\php\php-7.4.33-Win32-vc15-x64\php.exe`), Composer 2.8.3, Laravel 8.x, MySQL (`waranty_system` DB per `.env`).

**Spec:** No separate spec doc — the spec is the conversation decision: user explicitly refuses to upgrade their local PHP (currently 7.4) and asked to downgrade the project to Laravel 8 + PHP 7.4 instead, scoped as "milestone 1" (get it running, not a full feature-by-feature regression pass).

## Global Constraints

- Target PHP range in `composer.json`: `^7.3|^8.0` (Laravel 8's own supported range) — do not narrow to exactly `^7.4`, and do not require PHP 8.
- Target framework: `laravel/framework` `^8.83` (last Laravel 8 line).
- No automated test suite exists in this repo (`tests/` directory absent) — every task's verification step is a manual smoke check (booting the app, hitting a route, checking `storage/logs/laravel.log` for fatal errors), not a PHPUnit run.
- The project currently has **no git repository** — a git repo must be initialized and a baseline commit made before any file is changed, so the downgrade is reversible.
- Do not touch `compro-1/` or `compro-2/` (sibling, unrelated company-profile projects) or anything outside `dashboard/`.
- Preserve all existing business logic, routes, view markup, and database schema exactly — only change what's required to make the codebase parse and run under PHP 7.4 + Laravel 8.
- Do not introduce new abstractions, refactors, or "while we're at it" cleanups (e.g. the dead `CustomerPolicy`/`InstallPolicy` stubs, the duplicate QR libraries, the unused `layout/admin.blade.php` found during the earlier analysis) — those are separate, out-of-scope follow-ups.

### Task 5: Fix `match()` expression in `AutomotiveOrderCatalog`

**Files:**
- Modify: `dashboard/app/Services/AutomotiveOrderCatalog.php:28-36`

**Interfaces:**
- Consumes: nothing new.
- Produces: `AutomotiveOrderCatalog::areaOptions(string $treatmentCode): array` keeps the exact same signature and return values — `OrderController` and any Blade view calling it needs no changes.

`match` is a PHP 8-only expression (strict-comparison `switch` didn't exist as an expression before 8.0) and is a parse error under 7.4.

- [ ] **Step 1: Replace the `match` with a `switch`**

Change:
```php
    public static function areaOptions(string $treatmentCode): array
    {
        return match ($treatmentCode) {
            'KACA_FILM' => ['Kaca Depan', 'Samping Kanan Depan', 'Samping Kiri Depan', 'Samping Kanan Belakang', 'Samping Kiri Belakang', 'Kaca Belakang', 'Sunroof', 'Lainnya'],
            'PPF' => ['Full Body', 'Hood', 'Roof', 'Front Bumper', 'Rear Bumper', 'Door', 'Fender', 'Mirror', 'Lainnya'],
            'COATING' => ['Full Body', 'Exterior', 'Interior', 'Glass', 'Wheel', 'Lainnya'],
            default => [],
        };
    }
```
to:
```php
    public static function areaOptions(string $treatmentCode): array
    {
        switch ($treatmentCode) {
            case 'KACA_FILM':
                return ['Kaca Depan', 'Samping Kanan Depan', 'Samping Kiri Depan', 'Samping Kanan Belakang', 'Samping Kiri Belakang', 'Kaca Belakang', 'Sunroof', 'Lainnya'];
            case 'PPF':
                return ['Full Body', 'Hood', 'Roof', 'Front Bumper', 'Rear Bumper', 'Door', 'Fender', 'Mirror', 'Lainnya'];
            case 'COATING':
                return ['Full Body', 'Exterior', 'Interior', 'Glass', 'Wheel', 'Lainnya'];
            default:
                return [];
        }
    }
```

This preserves `match`'s strict (`===`) comparison semantics: PHP's `switch` compares with `==`, but every `case` here is a string literal compared against a `string`-typed parameter, so there is no type-juggling edge case that would make `==` behave differently from `===`.

Run: `grep -rn 'match (' dashboard/app` and `grep -rn 'match(' dashboard/app`
Expected: no output.
